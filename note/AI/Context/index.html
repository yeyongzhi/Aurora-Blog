Context【上下文】

含义

平常我们在和大模型对话的过程中会发现，它（大模型）好像会记住我们之前说过的话 比如你在开头和大模型说了，你叫**小明那么大模型在后续的对话中，也会称你为小明 但我们上文说到，大模型本质上是一个数学函数（不像我们人类具有记忆功能），那么它们是怎么记住我们之前的聊天💬内容的呢？

解答

实际上，程序（比如网页端的deepseek）在发送给大模型的时候，除了发送我们本次的消息内容，还会把之前的全部对话历史也一并发过去 因此，大模型每次看到的都是前前后后完整的对话内容，大模型才能知根知底。

定义

Context【上下文】代表的是**大模型每次处理任务时所接收到的信息总和**，也相当于是一个临时记忆体。 这个信息总和包含的内容很多：

  • 对话历史
  • 用户提出的问题
  • 当前正在输出的文字
  • 工具列表（Skill）
  • 以及一些System Prompt（系统提示词）等等
  • ...

Context Window【上下文窗口】

Context Window【上下文窗口】就是Context能**容纳的最大【Token数量】一般的主流大模型比如（GPT、Gemini）的上下文窗口都能达到100W

RAG

比如说现在我们有一个用户手册，几十万字需要丢给大模型，然后我们提出问题：这个产品的保修期是多久？ 让大模型消耗几十万Token去阅读这个用户手册这肯定不是最优解

  • 一是浪费上下文的Token数量，成本没法控制
  • 二是效率很低，这一本几十万字的用户手册其实真正关于保修期的内容无非就是几个片段而已 因此，解决方案就是RAG技术，它可以从几十万字的用户手册中找出真正有用的那几个片段，满足我们的要求的同时，还不会导致上面两个问题。
